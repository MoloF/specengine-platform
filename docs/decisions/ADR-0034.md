# ADR-0034

**Decision.** SpecEngine has no authentication of its own, now or later: no token, key, account, session, WebAuthn or Touch ID on any surface. `specengine-http` keeps its `127.0.0.1` bind, its Host, Origin and Sec-Fetch-Site fence and no CORS: they stop other sites' pages and identify no one. Protection beyond that is infrastructure per service (a WebAuthn proxy in front, if ever hosted). Supplements ADR-0017: the authentication its server mode would need is infrastructure's. Retires 07 s3's local token.

**Why.** Local, single-user use: the owner's own processes, agents included, read the corpus and the queue anyway. A token or login on every surface is code to keep and friction on every start, against threats (another account, hosting) that infrastructure answers better.

**Cost.** Any local process of any account can read everything served and stage a decision (loopback is not per-user); none confirms one from an ordinary shell, but one faking a terminal (`script`) can, as with `spec approve` today. Hosting or a shared machine needs infrastructure first.
