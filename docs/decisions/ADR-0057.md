# ADR-0057

**Decision.** Moving, cancelling and accepting a card from the local page, and clearing one once `card-trace` adds its route, are queue writes under a typed name nothing verifies, a convention until the hub's named login. `fence()` is the only guard, and any local process can post. No MCP tool reaches these routes. A departing accept, which `card-trace` will add, will create one proposal through the daemon, and `card-trace` must widen `door.rs`' `card_writes_touch_only_the_queue` to admit it. A card's person is no ID, so ADR-0009's Latin-only rule does not apply. A brief change stays confirmed on a terminal (ADR-0035).

**Why.** One person must run the whole cycle on one screen before any hub. ADR-0056 names moves alone; the owner's word names a login the local stage lacks, so a typed name stands in.

**Cost.** A name proves nothing: with a shell an agent can POST `assign` naming a reviewer, then `accept` as that name, skipping `spec card accept`'s `[y/N]`; `reviewer` and `by` stop slips only. The daemon writes beyond stages, so `#ui`, `serve.md#trust` and `door.rs` widen, for cards alone.
