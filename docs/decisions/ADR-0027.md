# ADR-0027

**Decision.** Tasks stay per project: its database and exported queue (ADR-0003), never gathered in SpecEngine's repository. SpecEngine hands a task out as a stack-neutral package with a schema version (MCP `get_task` + `get_context_bundle`, CLI `--json`): goal, targets, criteria, assumptions, open proposals, bindings, `spec_snapshot`, the bundle within budget. It writes no stack-specific text. Rendering and execution belong to the project's `.claude/` skills and roles or to a stack-profile plugin, versioned on its own and hosted outside SpecEngine's repository; SpecEngine's plugin (ADR-0015, amended) ships only stack-neutral roles and prompts. `specengine.toml` may name a profile, opaque to the core.

**Why.** Task skills differ by stack (Rust + Bevy, NestJS + React); stack logic in the core or its plugin bends it toward one project (ADR-0008), and skills scraping prose break on every wording change.

**Cost.** ADR-0015's one version of everything an agent sees gains a second seam: SpecEngine's plugin and a profile, joined only by the schema version; a breaking change bumps it and every profile follows. A project without a profile gets generic roles that take commands from its `CLAUDE.md`.
