# ADR-0045

**Decision.** `spec propose drift` (MCP `report_drift`) judges `HEAD` as `spec verify` does and queues one `drift` item per node whose lock pair no longer holds (`code_ahead`, `spec_ahead`, `conflict`, `broken_binding`), its evidence computed, never typed: one live item per node and branch, none again for evidence already settled. It writes only the queue and stops nothing. Approving an item, on a terminal where it was raised, runs `spec lock accept [--editorial]` for its node: one commit of the lock alone; nothing stored in the item is written. `spec reject --follow-up code|spec` settles it with a draft task.

**Why.** 05 s5.3 and 06 s4 send drift to the owner's queue with three outcomes; ADR-0041 has a drift decision run the same accept; ADR-0012 turns a decision against the code into a follow-up task, made ready only by the owner.

**Cost.** Amends ADR-0041 (approval writes the lock for a drift item) and ADR-0042 (findings are queued, still stopping nothing). One approval and commit per node; an item from a removed worktree is only rejected; never-locked work is queued only when named. Adds to ADR-0012, ADR-0032; supersedes nothing.
