# ADR-0047

**Decision.** `spec health` and its route list rows 4-6 of "What is left": markers naming a queue item, an archived node or one under an open proposal, with how it was decided; live nodes the project's `[[health.bound]]` rules select (kind, class, path, front-matter value) that no marker binds, not measured without a rule; plain `spec verify`'s findings but `ok`. It reads code, the queue and git, writes only the data directory's index; a row it cannot measure shows its causes, never 0. No exit 1, check finding, status, claim, approval, task or gate depends on it.

**Why.** 05 s5.3 and 06 s7 put the three on the panel; seeing a decision unlike the working answer starts ADR-0012's follow-up; which nodes need code is the project's word (ADR-0008).

**Cost.** Each Health read parses the code tree and runs git once, in the project's turn; row 5 floods until markers exist (ADR-0016); 05 s5.5's per-node `needs:` is not built. Adds to ADR-0008, ADR-0012, ADR-0042, ADR-0046; supersedes nothing.
