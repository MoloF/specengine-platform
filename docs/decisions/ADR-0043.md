# ADR-0043

**Decision.** `apply_proposal` raises the revision of each node whose `norm_hash` its change alters and never lowers one. `spec approve --editorial`, the owner's choice, keeps it and, in the same commit, sets the new `norm_hash` on that node's `spec.lock` entries that vouched for the old text at that revision. `spec check --staged` and `--changed` give an error for a node so vouched for whose `norm_hash` changed with neither. `spec bump` only lists nodes changed without a raise.

**Why.** 05 s3.5 has `spec bump` write revisions and `--editorial` write the lock, past the one door (ADR-0004, ADR-0041). An apply commit runs hooks, so an editorial change must prove itself in the staged tree; an accept after it comes too late.

**Cost.** Amends ADR-0041: apply writes the lock, beside its text. Unlocked nodes, `@N` pins and unhooked commits are not judged; a hand editorial edit of a locked node goes through the queue or `--no-verify`. Adds to ADR-0018, ADR-0019, ADR-0040; supersedes nothing.
