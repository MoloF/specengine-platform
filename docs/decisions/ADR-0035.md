# ADR-0035

**Decision.** The UI, and later an MCP form or URL mode, only stages a decision on an open proposal: one replaceable choice with the flags of `spec approve|reject`, kept in the queue. `spec approve|reject PR` on a terminal shows it whole with its time; its `[y/N]` is the only confirmation of a decision. Typed flags replace a stage, never merge; no `--yes`. Task approval stays the only control point (ADR-0012); spec files are written as before (ADR-0004, ADR-0005, ADR-0032).

**Why.** The owner reads and chooses best on a screen, but a browser tab or an agent's shell can be driven by any local process (ADR-0034); a terminal's question is the one step none answers by accident.

**Cost.** `specengine-http` becomes a queue writer; a decision takes two places; a reflex `y` can confirm a stage a page or an agent injected (shown whole with its time, an outside-change alert, the event log, no MCP stage tool); a faked terminal still passes. 05-08's elicitation consent is dropped.
