# ADR-0039

**Decision.** ADR-0037's gate holds for good, `spec serve` or not: a `command` `PreToolUse` hook runs `spec gate`, which reads the config, git and the queue itself, never the daemon or its discovery file: a verdict is the same with the daemon up or down. No verdict is closed: exit 2. A gated write opens only for an `in_progress` task claimed in the file's worktree, on its branch, of the same git common dir; no `[gate]` table: off; never `allow`; no proposal, `stale` or check read (ADR-0012). Threat model: a cooperative agent.

**Why.** ADR-0006 closes the hook "when the daemon is unavailable", ADR-0037 holds "until `spec serve`": shipping the daemon would tie every agent write to it, against 08 s3 AC-4 (no daemon needed). Only the browser needs the daemon.

**Cost.** One `spec` process per gated write for good, never a warm daemon answer; a gate on daemon state (a live index, sessions) takes a new ADR. ADR-0037's costs stay: the owner's sessions gated, another worktree's subagent refused, writers outside the hook pass, a wrapper maps every failure to 2.
