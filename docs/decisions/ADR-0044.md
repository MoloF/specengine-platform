# ADR-0044

**Decision.** `spec verify --tests [--task T]` runs each `@verifies`-bound test through the project's `[verify] tests`, an argv template filled from the binding: no shell, no runner named by SpecEngine. Only on a terminal, after one `[y/N]`, over a clean committed tree; never from MCP, the daemon, a hook, CI or a role. A test passes when its own run exits 0 within `[verify] timeout` and the command failed on a test that does not exist. Each run is a queue event. Its lock write is its own commit: a node's `[[tested]]` evidence added when its bound tests pass, removed when one fails; binding entries untouched. `verified` is computed from that evidence; no state, claim or approval reads it.

**Why.** 05 s5.4 names one runner (ADR-0008, ADR-0027); 08 AC-8 wants a pass SpecEngine saw itself; a configured command is code execution, the owner's to start.

**Cost.** One run per test, slow for large sets; a runner passing an empty filter needs a wrapper; commit first, a terminal; a test writing into the tree voids the write; a flaky failure costs a commit. Adds to ADR-0041 (a failing run removes evidence) and ADR-0042; supersedes nothing.
