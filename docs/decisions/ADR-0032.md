# ADR-0032

**Decision.** A proposal is bound at creation to the worktree, branch and base commit it was raised on, with its repository (git common dir). `apply_proposal` writes and commits only there, on that branch, and refuses when the worktree, repository or branch no longer match; it never falls back to the caller's worktree or the main tree. A task's proposals bind to the task's worktree. Supplements ADR-0004 (where the write lands); does not supersede it. Accepted under the owner's session delegation; owner review pending.

**Why.** 05 §7's "the main tree if there is no task" would land a spec edit away from the code it was raised beside, possibly in a tree the owner is editing; binding keeps the spec travelling with the code (ADR-0004) and makes the target checkable before any byte is written.

**Cost.** A proposal whose worktree or branch is gone can only be rejected and raised again (no re-targeting yet); each proposal stores four git facts; approving checks the recorded worktree, not the caller's.
