# ADR-0054

**Decision.** `review_proposal {proposal_id}` opens an elicitation form in which the owner picks; only the owner's `accept` stages, through the CLI library's `stage`, as the daemon does. No tool takes a choice from the agent; the tool carries `anthropic/requiresUserInteraction` on every call; `spec approve|reject PR` on a terminal stays the only confirmation. Supplements ADR-0035: this replaces its Cost's "no MCP stage tool" mitigation.

**Why.** The owner chooses in the session instead of starting the UI or typing flags. An agent-written stage adds nothing (`spec approve PR` already takes the working answer) and would pass the agent's pick off as the owner's.

**Cost.** The MCP server becomes a stage writer; a client can forge an `accept` (who calls is unknowable, ADR-0034) and the stateless `requestState` is unsealed: the terminal shows the stage whole with its time. A reflex `y` and crafted text steering the owner remain. `approve_task` needs its own ADR (RM-0038).
