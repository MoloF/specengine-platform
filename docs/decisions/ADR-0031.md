# ADR-0031

**Decision.** Node kinds are each project's vocabulary, declared per prefix in `[ids]`: the core knows none and validates no document's `kind:` (`kind-mismatch` stays the one kind finding); link types stay the model's shared table. Process rules (required keys, allowed values, labelled parts, own text) keyed by kind, class and path live in the project's `specengine.toml` as `[[check.rules]]`, name only declared kinds and set their severity, default error. Their findings are the project's own form findings (ADR-0022): mode and debt gate them like the convention's; content and task state never block (ADR-0006, ADR-0012). Settles core Q2.

**Why.** Projects keep record rules in their own checks (ADR-0013); a shared kind table would carry one project's structure into another (ADR-0008).

**Cost.** Each project spells out its kinds and rules; a misspelled `kind:` goes unnoticed; one record is judged differently per project; a part is found only by a heading or bold lead-in slug.
