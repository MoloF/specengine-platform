# ADR-0046

**Decision.** `spec bundle`, `show --bindings`, `tree`, `task show` and `impact`, and their MCP and HTTP twins, show each code binding of their nodes with its `sync`: `spec verify`'s plain state, computed per read over the refreshed code index and `spec.lock`, never stored. No exit code, status, claim, approval or gate verdict depends on it. A read of nodes never fails on the code layer (a bad `[code]`, a walk gap, an invalid lock, no git): its spec part and exit stay as they were, `sync` unknown with a note, never `ok`. `impact --since` takes a git revision, compared with the working tree.

**Why.** 05 s3.4 computes sync only; 05 s6 and 07 s1.2 put it where agents read. ADR-0042 bounds what a finding may stop, not where it shows; a read failing on code would withhold context exactly when code is broken.

**Cost.** Each such read refreshes the code index and parses `spec.lock`; a shown state may be newer than the last `spec verify`, and `bundle_hash` moves with drift. Amends ADR-0042 and ADR-0045: `spec propose drift` is no longer the only reader of verify's states. Adds to ADR-0012; supersedes nothing.
