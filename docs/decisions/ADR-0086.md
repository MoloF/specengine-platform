# ADR-0086

**Decision.** A crash, a hang or a leak is a critical defect, ranked above any logic bug; work causing one is not done. The daemon and a hub get soaks: a report per run, a written budget, a non-zero exit on a breach. Memory growth is a Theil-Sen slope, the median of all pairwise slopes, over the last two thirds of a run of at least 5 minutes, never two endpoints or least squares. A hypothesis takes two runs per variant. A stalled request captures a stack (`sample <pid>` on macOS). A finding is a task with its report, accepted by a clean re-run. ADR-0012 stands: this judges work, never a user's call.

**Why.** A hub serves up to ten people for weeks, where slow growth becomes an outage. One transient dip flipped a least-squares verdict between two runs of one build, and a single run once blamed the wrong cause.

**Cost.** About an hour of the laptop per soaked slice, one soak at a time. macOS's allocator is not the hub's glibc, so a Linux run is an owner's gate. Budgets are set by hand.
