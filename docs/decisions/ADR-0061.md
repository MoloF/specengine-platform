# ADR-0061

**Decision.** Narrows ADR-0035's "the only confirmation" and ADR-0038's "the UI only stages" on a hub alone; both stand for a local daemon, the CLI and MCP. A `lead` whose zones cover every path it governs (targets, an amendment's amended nodes, a staged `canon`), or the `owner`, confirms one staged choice per click: a route only a hub mounts takes a stage, never a choice, and applies it as a commit in the hub's own checkout, nothing pushed. No always-yes consent, no `approve` call in the daemon, no MCP tool.

**Why.** Zone leads confirm brief changes with no terminal (the owner's decisions 2, 3). Apply's steps run unchanged, so git is not the danger; a consent nobody gave is, so the library compares the question the page showed, byte for byte.

**Cost.** A person or a script: the route cannot tell, and a script holding a person's session passes, as a faked terminal does. A session-level step-up says a second factor is on the session, not that this click was a person's. A lead's confirm of a deciding kind writes a record under `[decision_records] dir`, which the cover does not judge. A forged `Remote-User` commits as anyone.
