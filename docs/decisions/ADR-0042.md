# ADR-0042

**Decision.** `spec verify` judges each code binding against `spec.lock`: a finding is Fix (broken by the change), Check (a human re-reads) or Pre-existing (already at `HEAD`, with `--changed`). `[verify] mode` reads as `[check] mode`: `observe`, the default, never blocks; `enforce-introduced` and `enforce` exit 1 on Fix findings only. A binding it cannot verify (an unparseable or ambiguous item, a node without a readable revision or hash, an unreadable file, another recipe) is never `ok`: exit 2 in every mode. No status, claim, approval or write depends on a finding; the gate never reads one.

**Why.** 05 s5.3 gives exit 1 "something blocks"; ADR-0012 blocks nothing on a discrepancy. Drift is shown, and a project decides whether its own CI or hook stops on it, as it does for form (ADR-0031). 08 AC-14: a run that could not look is no pass.

**Cost.** No red CI on drift until a project opts in; one unparseable bound item (about 1 % of valid Rust fails tree-sitter-rust) or a grammar bump holds verify at exit 2 until the marker moves or the lock is re-accepted. Adds to ADR-0012, ADR-0018, ADR-0031; supersedes nothing.
