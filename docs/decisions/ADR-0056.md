# ADR-0056

**Decision.** The work of any trade is a card, `C-NNNN`: a row in the queue database beside tasks, never a file or a commit. Project config gives each discipline its columns, its moves and who makes them; a refused move is a transition rule, and no `blocked` state enters the core. A move is a queue write the UI may make. A lead's move to `ready` is a card's control point; the gate never reads a card, and `spec task approve` stays `T-`'s. The requesting side accepts a result, never the assignee; evidence is references, never binaries. A rejected brief stops no card (ADR-0012).

**Why.** `T-` brings ten closed states, a worktree at claim, a terminal at approve and a pinned package, and a malformed row closes developers' gate. An artist needs none of that, and widening it risks the gate.

**Cost.** A second record in the queue, with its schema step, tools and screens; "task" now needs two words; a card proves nothing about code until phase two links it to `T-`; a project's `[ids]` may not claim `C`.
