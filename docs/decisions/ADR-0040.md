# ADR-0040

**Decision.** A node's revision is 1 to 999 999 999: a document's is its front-matter `rev:`, a section's the `rev=N` attribute of its own `{#ID ...}` heading (`## Regeneration {#RULE-STAM-REGEN rev=3}`), never its document's. None written is revision 1. One written but unreadable (not 1-9 digits, `0`, given twice, or front-matter that failed to parse) is unknown, never 1, reported as the parser's `bad-rev` or the front-matter finding. Neither a revision nor a heading line enters `norm_hash`.

**Why.** Sections carry bindings and drift (ADR-0026) without front-matter; the attribute versions the heading it sits on, as ADR-0026 foresaw for section metadata. None = 1 (the Phase 3 plan's convention, after tracey) so a corpus without revisions needs no edit and a marker's `@N` (ADR-0018) always has a revision to meet.

**Cost.** The attribute block is Pandoc/kramdown syntax GitHub prints as it prints `{#ID}` today; a node's first meaning change writes `rev=2`; `rev=0` or a repeated `rev` is a finding, not a guess. Adds to ADR-0018 and ADR-0026; supersedes nothing.
