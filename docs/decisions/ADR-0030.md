# ADR-0030

**Decision.** The index is the root at `[paths] index` plus the shards its generator entry lists; the root stays the one entry point, points to every shard, and a document has one line across the set. Tier 3 lines go to an archive shard when one is configured; live documents are claimed into shards by path globs, not by `scope:`, the first claim winning; the rest stay in the root. The root and each live shard are capped at `index_bytes`, the archive shard is uncapped; W's index term is the root plus the largest live shard. The cap, not §9's "~500 entries", decides when to shard. No shard: today's single file, byte for byte (ADR-0028 kept).

**Why.** The index is the one W term growing with n (§3): a pilot's ~500 record lines need 3–6 times the cap, and here every shipped spec still adds root bytes.

**Cost.** A sharded read costs the root plus one shard. The config lists each shard twice: in the entry and in its `writes`. `spec export index` reports and prints several outputs once a shard exists. The archive shard grows O(n), outside W.
