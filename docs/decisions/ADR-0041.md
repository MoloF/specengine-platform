# ADR-0041

**Decision.** `spec.lock` is neither a spec file nor a generated document: it records what was verified, and only two writers change it. The owner's `[y/N]` on a terminal: `spec lock accept`, hashing only committed bytes and naming that commit, and `spec lock regen`, which merges a conflict's entries and hashes nothing. And a passing `spec verify --tests` run. Each write but a merge's is its own commit of the lock alone, with provenance. Never `apply_proposal`, an MCP tool, a role, `spec check`, CI or a hand edit.

**Why.** The lock makes "the spec matches the code" a fact at a commit (ADR-0018); if an agent, a proposal or a rebuild from the current tree could write it, drift would become "verified" with no one deciding.

**Cost.** Code is committed before it is accepted; one prompt and one commit per node; a lock conflict waits for the owner's terminal; a later owner step confirming a lock change (an editorial approve, a drift decision) must run the same accept. Adds to ADR-0001, ADR-0005, ADR-0018; supersedes nothing.
