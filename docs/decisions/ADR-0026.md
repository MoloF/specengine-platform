# ADR-0026

**Decision.** Unchanged from ADR-0002: a record of a project-scoped prefix is one file; a node document (mechanic, feature) is one file whose rules are `{#ID}` sections. New: an ID whose prefix has `scope = "feature"` in `[ids]` is defined only as a `{#ID}` section of a feature document, a file `<slug>.md` directly under `[paths] features` (slug = the file stem, `[a-z][a-z0-9-]*`). It is unique within that file, has no record file, and is cited `<slug>/ID` from other files, bare in its own.

**Why.** Criteria are written, reviewed and shipped with their feature; the pilot corpora already number criteria per feature (08 §4.1, §4.3 (e)); the stem as slug needs no registry.

**Cost.** All criteria of a feature share a file (the per-section hash keeps drift local, 05 §2). A section has no front-matter: a criterion's `status`, `owner` and declared links become heading attributes later, or weak inline mentions now. Renaming a feature file breaks every `<slug>/` citation (visible as findings). A bare feature-scoped ID can name several nodes in `lookup_id`.
