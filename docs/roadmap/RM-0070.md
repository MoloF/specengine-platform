# trial-followups (Phase 7): what the second trial and earlier review left

None of this blocked the gate of 2026-10-31 (step 7e, 08 s2 Phase 7): the first result closed with all of it open. It depends on nothing open and blocks nothing, the hub included. 2.5-3.5 pipeline hours.

- **The skill may not be found.** `write-flow`'s description says "Write a flow of spec documents" while an owner says diagram, stages, start and end. The descriptions' budget is 1 200 B in total, no byte free (`docs/canon/plugin-files.md`), and `INSTRUCTIONS` is at its cap, so a wider line cuts another.
- **A group reads emptier than it is.** `get_flow trace:true` prints a group as `rollup no card` while it holds marked steps; the screen's boxes count what they hold.
- **A section hides its document's cards.** `get_trace` on a section reads `no card` right after an edit of it marked its document's card: a section row should show its document's cards.
- **A mark does not name what changed.** The card reads `on: NODE-hold` when only its nested section moved.
- **Nothing says a card needs a reviewer.** A reviewer is a person's to set, deliberately: `spec card assign` or the page's Assign, no MCP tool names one (ADR-0057). `move_card` into review answers only `moved`. A note on that move, or a default reviewer in `[[card.flow]]`, which fits ADR-0056.
- **The trace's counts.** The header's counts no longer sum to the rows, since holders count nowhere, and no source an AI is given says so; the canon says it of a lane alone (`docs/canon/spec-trace.md` "The read"). `get_trace stage:"-"` printing no rows cannot be told apart from a definition not being a flow step.
- **The counts' cost.** `spec flow --trace` and `spec trace` count each node's held documents again (CLI `trace.rs` `counts`, `held_documents`): O(nodes × held), quadratic in `parent:` depth, where `flow-linear` (RM-0076) made the rest of the read linear (`docs/canon/spec-flow.md` "Known limits"). One pass per read in place of a walk per node, with RM-0076's golden (`crates/specengine-cli/tests/flow_linear_before.json`) staying byte-equal; 0.5 hours.
- **`spec approve` and the `--open` walk hide a stored finding.** An item with a stored `ref-dangling` asks only `apply ... (new file)? [y/N]`. One line at the consent.
- **A reject-staged row.** Plain `spec approve` on one: the note never says it was a reject.
- **A declined holder in the walk** leaves a later item with a dangling reference and no note (`docs/canon/proposal-apply.md` "Known limits").
- **Cards have no walkthrough.** One line in `read-spec`.
- **Nothing says a stage may be any script.** The first trial wrote five stages in Russian, and they worked in `spec flow`, `spec trace` and on the Timeline. No source an AI is given says so (the canon does, `docs/canon/spec-flow.md`; `write-flow`'s example has `stage: a`), so the second trial's AI chose Latin keys and a Russian writer read them on the diagram. Open: a label for a stage.
- **The gaps panel** with remedy lines stands 200 px taller than the left column at 1440x900 and scrolls with the page; it has no scroll of its own.
- **Owner's call, kept open.** One consent over a shown set of new-file creates would need an ADR amending ADR-0038. The second trial took 19 consent keys, the first flow's 16 proposals in one walk.

Deferred to the next release, `v4`, on 2026-11-04: the owner's instruction to do only what the hub's release to a server needs (08 s2 Phase 7, "Release scope").
