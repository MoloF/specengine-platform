# collision-pass (Phase 7, v5 step 9): candidates, a pair ledger, a skill

Candidates come from the graph (same kind sharing `uses`, a group or a term) plus search, at most N pairs. A ledger keyed by the two `norm_hash` values re-checks only changed pairs, so the cost follows changes, not n squared. An agent outside SpecEngine reads the pairs and files `report_discrepancy` with `gap_type: contradicts`; false positives are bounded by caps and the ledger. 3-5 pipeline hours.

Deferred to the next release, `v4`, on 2026-11-04: the owner's instruction to do only what the hub's release to a server needs (08 s2 Phase 7, "Release scope").

Since 2026-11-10: `v5` (08 s2 Phase 7, "v5 scope"), the owner's pipeline step 3: a new entity is compared with what exists, reuse offered, collisions resolved with the reason shown. The order is RM-0059, RM-0060, then RM-0088's plain questions and pairs.
