# hub-mcp (Phase 7, step 11): `/mcp` with a session, identity to author, hub tools

MCP over the network at `/mcp/<slug>`, a hub's alone: both protocol eras, a legacy session bound to the login that opened it, the proxy's identity becoming the author and the card's actor, 17 tools that decide nothing, and their own instructions (the stdio text has none left). Calls run inside the per-project turn. Every hub tool leaves `git status` empty (08 s3 AC-3). Whether a writer's client attaches a remote MCP with a per-person credential is unmeasured, the largest unknown in the plan. It is checked by hand after the daemon side is built, since RM-0064 depends on this step: Claude Code on the laptop through a local TLS proxy, claude.ai on RM-0064's public origin. Spec: `docs/features/hub-mcp.md`. 6-9 pipeline hours.

- **A duty from `hub-confirm`.** A `/mcp` credential yields the same `Remote-User` as a person's session, and the daemon cannot tell them apart, so only the proxy can keep it off every other path, the confirm routes first. This step scopes that credential as trust item 6, and RM-0064's rules carry it.
