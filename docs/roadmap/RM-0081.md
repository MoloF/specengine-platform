# workspaces (Phase 7, v4 step 1a): a workspace per trade, modules, and Tasks off the nav

Shipped 2026-11-09 (`docs/features/workspaces.md`; `docs/canon/workspaces.md`), issuing ADR-0073 `workspaces`; Q5 and Q6 are the orchestrator's working answers, awaiting the owner's review.

- **A lens, never an entitlement.** `[[workspace]]` in `specengine.toml`: the nav's sections in order, a landing, the card flows the Board shows, a default module. Every section keeps its route and palette entry (ADR-0012). A Workspace select in the shell, per viewer in `localStorage`; a hub login's default waits for RM-0089, `[team]` untouched (Q6).
- **Read apart, failing nothing.** `ProjectConfig` only checks the names; a bad table serves the implicit workspace (every section but Tasks) or no module, with a note. `spec workspace [--json]` and `GET .../workspaces`, which takes no turn.
- **Tasks off the nav** (decision 3), still a route, in the palette and the Inbox's links.
- **Modules** (Q5): `[[module]]`, one root and its subtree, roots the Tree and Flow reads; no table, no bar. The kind selector waits for a route that reads the corpus.
- **The gamedev preset** `scripts/presets/gamedev.toml`: five card flows from the role research and four workspaces, the lead's named `production`; `spec init --pack` stays RM-0061's.
- **Risk kept.** An older `spec`, daemon or MCP refuses a config holding the tables: a hub-served project adds them only after its hub upgrades.
