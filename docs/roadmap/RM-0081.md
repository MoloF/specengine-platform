# workspaces (Phase 7, v4 step 1a): a workspace per trade, modules, and Tasks off the nav

Today every person sees the engine's nine sections, whatever their trade. A writer does not need Health. The owner decided on 2026-11-08 to start with four roles: writer, developer, artist or level designer, and lead (the owner). Issues the ADR `workspaces`. 4-6 pipeline hours.

- **A lens, never an entitlement.** A workspace holds sections in order, a landing section, the card flows it shows and a default module. It hides no route and is no control point (ADR-0012). Locally, "View as" is kept per viewer in `localStorage`, as the board's actor is. A hub's per-login default waits for RM-0089, and `[team]` is untouched (Q6).
- **Project config, read apart.** Workspaces are tables in `specengine.toml`, read apart the way `[flow]`, `[card]` and `[team]` are; `ProjectConfig` only checks their names. A bad table serves the implicit workspace plus a note and fails nothing. The daemon serves the workspaces, with a read-only CLI twin like `spec team`, and 07 s3 names the route before the UI calls it.
- **Tasks leaves the nav** (the owner's decision 3). Its route, the palette and the Inbox's links stay. A task shown inside its card is step 3's.
- **Modules** (Q5). A module is a configured root document, or a kind selector, together with its subtree. Choosing one scopes the Tree and Flow reads. With no table, no module bar is shown.
- **A gamedev preset** is a fixture-tested TOML file outside the core crates, taken ahead of RM-0061's pack; `spec init --pack` stays RM-0061's. Its card columns come from the role research:
  - narrative: Backlog, Outline, Draft, Review, Approved, Ready for dev, In game;
  - development: Backlog, Ready, In progress, In review, Verify, Done;
  - art: Waiting, Ready, In progress, Pending review, Approved, In engine;
  - level design: Layout, Blockout, Playtest, Scripting, Lighting, Art pass, Final;
  - lead: To do, In progress, Review, Done.

  The lead's workspace takes a name that does not echo `[team]`'s `lead` role.
- **Guards.** A non-game fixture. `no_domain.rs` and `policy.test.ts` widen to workspace and module names, and no fixture kind is named like a route.
- **Risk.** An older `spec`, daemon or MCP refuses a whole config that holds the new tables (`deny_unknown_fields`). The tables must not be committed to a hub-served project before the hub upgrades.
