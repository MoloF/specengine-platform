# departments (Phase 7, v5 step 4): the owner's words, department statuses and directions

The spec is `docs/features/departments.md` (draft, 2026-11-11, DP-1 to DP-16), with ADR-0076 `departments`, which amends ADR-0073 (`docs/canon/workspaces.md` "The lens"). The owner's words of 2026-11-10 replace today's: "Project", "Task" for a card, "Subtask" for a child card, "Agent task" for a `T-` task, and "Department" for a workspace lens. A department stays a lens, never an entitlement (Q3). 10-14 pipeline hours.

- **The chrome's words**, in both catalogs: Department, Task, Subtask, Agent task and Directions; the nav's Tasks reads "Agent tasks", its route unchanged.
- **Config keys.** They stay as they are: `[[workspace]]` keeps its name, with no `[[department]]` alias. A new top-level key would make an older binary refuse the file.
- **`[[card.flow]] title`**, optional: a flow's display name, served in `list`'s `flows[]`; the Board's tabs show it.
- **Directions.** `[[module]] kinds = [...]` is a module chosen by node kind, with no root, served as `modules[].kinds`: the Spec tree lists its nodes, a document's Inside groups them under its title, and Flow takes rooted modules only. Flow's kind cut is RM-0102, in the pool.
- **Hand-off** picks a department: the daemon serves each department's `disciplines` by the new-card rule.
- **Presets** give their flows titles; a direction is a commented example.
- **Plugin vocabulary.** `read-spec` says a card is the UI's task, a child card its subtask; plugin 0.35.0.
- **Rollout.** A new key follows ADR-0073's rule: an older binary refuses `title` and drops every module on `kinds`, so `spec` and the plugin are installed from one commit.
