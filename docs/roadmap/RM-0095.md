# doc-modal (Phase 7, v5 step 3): one document modal everywhere, with the path as its breadcrumb

Shipped 2026-11-11 (`docs/features/doc-modal.md`; `docs/canon/doc-view.md`, `spec-flow-screen.md` "Panel"). No ADR. Flow v2 step 3d, with RM-0091 `english-polish` and RM-0101 `gap-titles`: the owner found the documents in Flow's right panel unreadable (2026-11-10) and asked for one modal holding everything, a minimal panel, technical fields out of the way. Plugin 0.34.0; first-load JS 824.13 kB of 845.

- **The reads** serve each link end's `title` and `end_kind` (`show --links`, `get_node`, the daemon's nodes read, `spec health`'s amendment links) and each gap row's `titles` (RM-0101): JSON only, from parses the reads already hold.
- **The modal** is the `doc` hash pair on any project route, with a page at `#/<p>/tree/<REF>/page`: the breadcrumb from `ancestors`, work state and status, the text at reading width, links by title, Cards, Inside (children by section, then raw kind, read on expansion), technical details folded. It is always the top dialog, over a card modal too.
- **Links.** `DocLink` serves every document link outside the Spec tree; 16 tree links in 13 files stay on purpose. A plain click opens the modal, a modifier or middle click the page; the palette opens the modal too.
- **Flow's panel**: title, stage, work state, marks, the first paragraph, Open document, New card, a group's Open. Gaps titles members from the read, with no tree read.
- **RM-0091's** thirteen English `_one` forms are fixed, each pinned by a test.
