# Drift screens in the web UI (Phase 4)

Each node's drift shown where the owner already reads (node, inbox, tree), read-only, over reads the daemon serves. These are the Node tab's bindings, the Queue card's evidence and the Tree's `sync` from 07 s3. It was split 2026-10-21 (owner pre-approved, review open) into three slices, UI only, with no ADR, in this order:

1. `ui-node-bindings`: the node's Bindings tab with its rows, `[[tested]]` entries and copyable commands; shipped 2026-10-21 (`docs/canon/drift-screens.md`).
2. `ui-drift-evidence`: a drift item's stored rows typed, and Health row 6's remaining fields, drawn by one row component; shipped 2026-10-21 (`docs/canon/drift-screens.md` "Drift rows").
3. `ui-tree-drift`: opt-in tree badges from Health's row 6, each node's own rows; shipped 2026-10-21 (`docs/canon/drift-screens.md` "Tree badges").

It takes the deferrals pointed at it:
- no node screen (`docs/canon/code-reads.md` "Twins"), met by slice 1;
- drift rows untyped until Phase 4 (`docs/canon/proposal-drift.md` "UI"), met by slice 2;
- row 6's `markers`, `node_rev`, `lock`, `compared`, `levels` and `pre_existing` (`docs/features/health-drift-ui.md` "Description and interactions"), met by slice 2.

It passes these on:
- the lock diff inspector (RM-0033);
- tree counters in `spec tree`, `get_tree` and the daemon's tree (RM-0034);
- the history tab (RM-0035);
- `spec impact`'s HTTP route and the graph's impact mode, which `docs/features/impact.md` "Out of scope" left here (RM-0036);
- the node evidence level (RM-0037).
