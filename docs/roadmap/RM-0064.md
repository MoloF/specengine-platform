# hub-deploy (Phase 7, step 11b): Docker compose with Traefik, from a clean VPS to a hub

A `deploy/` directory and the `.github/workflows/image.yml` workflow take an operator from a clean Linux VPS with Docker to a running hub in one sitting: `Dockerfile`, `docker-compose.yml` with `specengine`, `traefik`, the login door and a one-shot `admin` service (RM-0065), `.env.example` (domain, ACME email, repository URL, image version), Traefik config with Let's Encrypt TLS, a step-by-step README. When built, `deploy/` needs a role's write list and a `roots` entry. A first real project stays small until `scale-reads` (RM-0054). 3-5 pipeline hours.

- **Documents.** A host folder holds each project's checkout, bind-mounted; a separate named volume holds the data directory (SQLite index and queue), on a local disk, never a network share. A guide and script bring a project over: the sparse clone of `docs/` and `specengine.toml` (`hub-git`), then `spec export state` and `spec import-state`, whose consent is a terminal, so under an interactive `docker compose exec`. No path is rewritten (ADR-0032): an open proposal arrives an orphan, only rejectable, so the guide decides them before the dump.
- **To settle: the bind.** The daemon binds 127.0.0.1 (ADR-0034) and `hub-identity` (ADR-0059) left that bind alone, assuming the proxy on that host, but Traefik in a second container is not on its loopback. Recommended: `network_mode: "service:traefik"`, which keeps the bind and ADR-0034's letter and publishes no daemon port, on two conditions: restarting `traefik` alone can leave `specengine` without a network, so the restart test covers it; and Traefik reads a file provider, never the Docker socket, because the host is agent-free. An internal compose network needs a bind change and a new ADR.
- **To settle: identity.** Traefik terminates TLS but logs no one in, so `hub-identity` needs a forward-auth companion in the compose file. Recommended: Authelia as the self-hosted login door, because recovery from the server must never depend on an outside account; for that reason oauth2-proxy over an outside provider is rejected as the primary door. Authelia's access-control `resources` rules match request paths by regular expression, which is how `hub-confirm`'s step-up on confirm routes is expressed (checked against its docs on 2026-10-31). Traefik removes a client's copy only of a header listed in `authResponseHeaders`, so `Remote-User` is listed there and only the forward-auth response sets it. Two things stay to verify at the start of this step: passkey login, and removing a lost passkey from a command line. If either fails, the step names the alternative before building.
- **To settle: the host.** It still runs no agent and nothing else untrusted (ADR-0059): the compose file is the whole host, and the daemon's port is never published.
- **What `hub-identity` stands on.** The daemon cannot tell the proxy's header from any process reaching its socket, so this step guarantees `docs/canon/hub.md#trust`: the port unpublished and nothing but the proxy in that network namespace; `Remote-User` in `authResponseHeaders` on every router reaching the daemon, no router or `bypass` rule without forward-auth; `passHostHeader` left on, so the daemon sees the public `Host`; no agent on the host. The daemon starts with `--public-origin` naming the final domain.
- **The login's sibling subdomain.** The login door sits on a sibling subdomain of the hub, so its landing arrives as a `same-site` navigation, which the hub admits on `GET /` alone and refuses everywhere else. Tried by hand in a browser here, as is what the door answers to a JSON request when a session has expired: a redirect fails as status 0 in the page.
- **Hardening headers.** `nosniff` on JSON and COOP on the page, set at Traefik or the daemon (`docs/canon/hub.md` "Known limits").
- **A launcher on the host.** `spec serve --root <served>` attaches to a hub: it exits 0 with `already running` and a loopback URL that answers 403, and another root is told to stop the hub. `daemon.json` keeps its five keys and this fails closed, so the README names it.
- **Secrets.** The git deploy key the hub pushes with is a Docker secret, never in the image or `.env.example`.
- **Operations.** Restart policy and a health check through Traefik, because a hub answers a loopback `Host` with a 403; a probe with no session stops at the login door, so this step settles what counts as alive. An off-host dump every 15 minutes of the queue, the login store and the deploy key's location, because losing the VPS must not force everyone to re-enrol, the login store's dump encrypted because it holds password hashes and passkey records; an upgrade dumps first, because queue migrations run forward only.
- **Image.** The repository is public: `image.yml` builds on a version tag, for linux/amd64 and linux/arm64, and publishes to GitHub Container Registry, so publishing happens only when the owner pushes a tag. The image carries `spec`, `specengine-http` and `git`, a second channel beside ADR-0015's `cargo install`. No Rust toolchain or `rust-analyzer`: code binding on the host is out of this item. The server only pulls: the compose file pins a version from `.env`, never `latest`, and with no registry the fallback is `docker save` piped over SSH to `docker load`. The VPS does not build: a Rust and UI build is not a job for 2 vCPU and 4 GB.
- **Domain.** Passkeys and any OAuth callback bind to it, so it should be final before people enrol; a free dynamic-DNS or IP-based name is for a dry run only.
- **Sizing.** At least 2 vCPU, 4 GB of memory, 40-80 GB of local SSD, from a measurement on 2026-10-31 on a laptop, not a VPS: a 5 050-document synthetic corpus, index 20 MB, daemon 99 MB resident plus 35-50 MB per request, reads serialised per project.
- **Done.** On a clean VM, `.env` filled in and `docker compose up -d` serve the UI over valid TLS; the daemon's port is unreachable from outside; a client's forged `Remote-User` is dropped on every router, with and without a session; a person lands on the board after login in a real browser; restarting the stack, or `traefik` alone, keeps the hub serving and the queue; a restore from a dump brings back the queue and the accounts. Only people can do: buying the domain, DNS, the VPS itself.
