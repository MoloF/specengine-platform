# hub-deploy (Phase 7, step 11b-1): Docker compose with Traefik and Authelia, from a clean VPS to a hub

Shipped 2026-11-03 (`docs/features/hub-deploy.md`, ADR-0066, ADR-0067, `docs/canon/hub-deploy.md`, the guide `scripts/deploy/README.md`). One compose file is a hub's whole host: Traefik on its file provider alone, Authelia with a step-up rule on exactly trust item 5's regex, and the daemon in Traefik's network namespace on its loopback bind, its port never published. A per-person random secret, checked by Traefik on item 6's routers alone, sets `Remote-User` for MCP clients; every other router takes the door's cookie session. The image (`spec`, `specengine-http`, git; no toolchain, no git-lfs) is built by `.github/workflows/image.yml` on a `v` + plugin-version tag for amd64 and arm64 and published to GHCR, never replacing a published version. An entrypoint serves each project folder; a clone script makes a full, sparse checkout with its upstream. A restored dump's `Author.login` is checked on decode. Every trust item a test can reach is pinned with no network or Docker; the third-party pins await the owner. Decisions are the orchestrator's working answers, the owner's review open.

Still open, outside this item: dumps, restore, upgrade, health and turning on `--push` (11b-2, RM-0074, waiting for the owner's dump destination); the gate, step 11b-3, the owner's session on a clean VM and the VPS (H1-H17 of the task spec, with the claude.ai client check), which `--push` and real people wait for. Only people can do: buying the domain, DNS, the VPS itself.
