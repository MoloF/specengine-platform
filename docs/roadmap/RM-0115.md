# door-step-up (patch 0.46.1, a fix): a step-up refusal says what to do and links the door

The owner hit this on 2026-11-14, on the hosted hub (0.46.0, Authelia 4.39.28 behind Traefik forward-auth). He confirmed a staged proposal with a session signed in by password alone, and the door refused the confirm read with a 401. The body was `<a href="https://<door>/?rd=<the API URL>&amp;rm=GET">401 Unauthorized</a>`. The confirm dialog showed that HTML verbatim, as text: not clickable, and its `rd` would bring the person back to the API URL rather than the page.

The canon assumed the door redirects, which the page sees as status 0 "No answer". It was wrong.

The fix covers the four step-up acts: confirm, card accept, card clear and the trace's clear. On a 401, or the old status 0, the page says the act needs the second factor. It gives a real link to the door that returns to the current page, then Retry, and never shows the body. The canon is corrected at ship.

Spec: `docs/features/door-step-up.md`, no ADR. It ships in the patch release 0.46.1 with the other items RM-0114 to RM-0119.

Shipped 2026-11-14 in the 0.46.1 patch: `api/door.ts`, one `Refusal` on the four acts, the door in a new tab. Canon: `docs/canon/hub-confirm.md` "Screen". Owed: DS10, the owner's on the live hub.
