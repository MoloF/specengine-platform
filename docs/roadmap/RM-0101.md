# gap-titles (Phase 7, v5 step 3): gap items serve their members' titles

A follow-up of RM-0094 (`docs/features/flow-scenario.md`, its departure 14). A flow read's gap rows name each item's members by name alone. Flow's Gaps control shows titles, and a member that no read in hand titles (a document folded into a group) makes it read the whole tree once while the control is open: one O(N) read, heavy at 100k (`docs/canon/spec-flow-screen.md` "Known limits").

- **The read.** Each gap row serves `titles`, parallel to `items`, the member's title or `null`; the text is unchanged. It is a key a tool returns, so the plugin takes a MINOR (`docs/canon/plugin-files.md`).
- **The screen** titles every member from the read, and the tree read leaves Flow.
- 2-4 pipeline hours, Rust first, then a small UI change. In the pool from 2026-11-10; the same day it was taken into RM-0095 `doc-modal`'s Rust lane (`v5`, `must`), whose link-end titles take the same plugin MINOR, 0.34.0: `docs/features/doc-modal.md` (D5, DM-3, DM-15). If that lane runs out of iterations on it, it returns to the pool.
