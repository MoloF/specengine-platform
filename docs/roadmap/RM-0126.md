# git-reads (deferred from 0.47.1): in-process git reads on the write path

On 2026-11-15 the owner said "step c, can also be done right away". The working answer deferred it, and his review is open. The reasons:
- after `write-cost`'s cuts, a hub spawn costs 2-5 ms, so (c) buys only 0.01-0.07 s per call;
- against that it adds a C library, about four lock packages, three amended dependency tests, `stack.md`, an oracle over about 20 repository states, and a stale-read risk under concurrency.

It comes back if he insists after hearing the numbers.

**Library:** `git2`, `default-features = false`.
- It adds `git2`, `libgit2-sys`, `libz-sys` and perhaps `jobserver`; the rest is already locked.
- It is pinned with `=` to the newest at adoption, with 0.20.x and libgit2 1.9 as the floor.
- `gix` is rejected: 50+ packages, an MSRV that tracks stable, monthly breaking releases.
- The tests to amend: `crates/specengine-cli/tests/show_bindings.rs`, `crates/specengine-cli/tests/proposal_genre.rs`, `crates/specengine-eval/tests/build_graph.rs`.

**What moves in-process:**
- `branch`;
- `commit_of` and `head`, for `HEAD`, `refs/heads/*` and full OIDs;
- `operation_in_progress`'s names;
- `parents`, `name_status`, `blob_at`, `has_path`, `blob_oid`;
- `ls-files` (a split or sparse index still spawns);
- `committed_tree`.

**What stays a process:**
- `--local-env-vars`;
- the top and the common dir;
- trailers, `status`, the committer identity;
- `merge-file` and `diff --no-index`;
- every write.

**The effect.** Spawns fall from 11 and 25 (a question's GET and POST) to about 5 and 9. Under concurrency the repository is opened per call, with no cached refs, packed-refs or object database.

**The draft decision**, for the next free ADR number:

> **Decision.** `WorktreeGit` reads, through `git2` pinned in `stack.md`, a branch and a commit ID, a commit's parents, a blob or tree at a commit, a path's index entry. The repository is opened per call on the git dir that call's `git rev-parse` named; nothing is cached across calls, no `git2::opts` set. Each answer must equal the `git` CLI's, held by an oracle. `git` still runs for discovery and ownership, `status` and trailers, the committer identity, `merge-file` and `diff --no-index`, and every write, `commit --only` with its hooks among them. A repository libgit2 cannot read (reftable, SHA-256, a split or sparse index) is read by `git`.
>
> **Why.** Each read was a process.
>
> **Cost.** A second reader of git's formats; a C library beside SQLite.

**Criteria** (`write-cost` WC31-WC34):
- **A git oracle over the repository states.** Each mutation turns it red: reading `<ref>.lock`; ignoring packed-refs; per-worktree names under the common dir; skipping the ownership or `extensions` check; a process-wide cached repository.
- **An open counter** equals the call count, and another process's commit is seen both between and within calls.
- **The dependency tests and `stack.md`** are amended, and the build passes on rustc 1.90 and in the hub image.
- **Spawn counts** are 5 and 9.
