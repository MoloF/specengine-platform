# doc-library (patch 0.47.2): every document as a library, with its decisions and tags

This item comes from the owner's word of 2026-11-19, wish 1 (08 s2 Phase 7, "Owner's word, 2026-11-19"). He wants "how it works now" shown as documents, with classes and tags, and each with the decisions that changed it. A fresh summary already exists as canon, and its decisions already point at it with `canon:`. What is missing is a way to browse them.

**Ships:**
- a typed `tags:` front-matter list, stored in the index and never counted in `norm_hash`;
- `spec library [--archive] [--json]` and `GET /api/projects/:p/library`: one row per document, its front-matter facets, uses, last change, served modules, and the decisions whose `canon` lands on it, split by status, with a "behind its decision" mark;
- a Documents section in the UI.

It needs no ADR and no MCP tool. `INDEX_FORMAT` goes to 18. On a hub the read is trusted, adds no cache of its own, and is held by a memory soak.

Spec: `docs/features/doc-library.md`. RM-0128 and RM-0129 wait on it.

Shipped 2026-11-19. Canon: `docs/canon/spec-library.md`. `INDEX_FORMAT` 18; no MCP tool or plugin file changed, so it goes out as plugin 0.47.2, a version-only bump, the next tag `v0.47.2`. The main session commits, tags and upgrades the hub, on the owner's word of 2026-11-20. DL14: slopes 0.0 and 0.062 MiB/min against 0.5.
