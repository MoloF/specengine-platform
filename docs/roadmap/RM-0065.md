# hub-accounts (Phase 7, step 11c-1): accounts and recovery from a shell on the host

Shipped 2026-11-03 (`docs/features/hub-accounts.md`, ADR-0068, `docs/canon/hub-deploy.md#accounts`, the guide `scripts/deploy/README.md`). A hub's accounts are the deployment's script `hub-admin`, run as `docker compose run --rm admin <act>`: a one-shot service with no network, port or log driver, on the door's own image, whose CLI hashes passwords and deletes passkeys and TOTP. Root is the host's shell, and the acts that write refuse without a terminal. The script adds, disables, enables and resets people, issues and revokes the per-person MCP secret, shows the door's one-time code, lists accounts, and checks `[team]` against them through the new read-only `spec team`. It never writes `[team]`, keeps an act log, and works with the door down. The door re-reads a person on every request, and its users folder is read-only to it, which closes 11b-1's possible default user. No crate holds account code. Design B and every decision are the orchestrator's, the owner's review open; ADR-0068 awaits the owner's confirmation.

Still open, outside this item: a stream's maximum life (11c-2, RM-0075); VF1-VF3 on the pinned images and G1-G10 at the gate, step 11b-3; dumps of the MCP users file and the act log (RM-0074).
