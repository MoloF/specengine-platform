# store-reads (Phase 7, step 12d): `show`, `--links` and `bundle` read a subset from the index

Split from RM-0054 on 2026-11-03 (the orchestrator's decision, awaiting the owner's review). Today each read re-reads and re-parses every file (`with_bytes`, CLI `corpus.rs`) and resolves every link; plain `show` builds a resolver over the whole input. Here `spec show`, `show --links` and `spec bundle`, with their MCP and daemon twins, read a subset input from the index and RM-0078's edges. 1.5-2.5 pipeline hours.

- **T3.** One index snapshot per read.
- **T5.** Every printed byte matches the BLAKE3 of the row it came from. On a mismatch the path is updated and the read retried; if that is not enough, the read walks.
- **Whole-corpus reads (Q7, the orchestrator's, awaiting the owner's review).** `tree`, `graph`, `impact` and `flow` use the indexed parse when a file's BLAKE3 matches its row, and stay O(N).
- **Done.** Each changed read's text and JSON equal today's on every fixture and on RM-0077's corpus; a file changed under a read is never printed from its stale row.
