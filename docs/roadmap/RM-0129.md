# specengine-guide (Phase 7, pool): SpecEngine's own user guide, served read-only beside a project

This item comes from the owner's word of 2026-11-19, wish 3 ("a must"; 08 s2 Phase 7, "Owner's word, 2026-11-19"). A project adopting SpecEngine gets a knowledge base it can cite for "where does X go", instead of keeping it in people's heads.

**Intent:**
- `docs/guide/<topic>.md` in this repository: class canon, Tier 2, in English. Each page covers one feature: what it solves, when to use it, how (CLI, MCP, screen), where it lives, and what not to do. Each rule is a `{#ID}` section, and the front-matter names the canon sections the page summarises.
- The guide is embedded in the build and served read-only:
  - by `spec guide [TOPIC]`, which works with no project;
  - by an MCP tool on stdio and on the hub;
  - by a daemon route;
  - on a "SpecEngine guide" shelf in Documents (RM-0127).
- A warning when a summarised canon page was reviewed after its guide page.
- Guide citations take a form outside a project's `[ids]` (`guide:<topic>#<ID>`).

**Needs a new ADR:** SpecEngine's guide ships in the build and is served beside a project's corpus, never inside it. It touches ADR-0001, ADR-0015, ADR-0022, ADR-0024 and ADR-0027. The guide is canon, not a new class, so the convention is unchanged.

**Out:**
- copying the guide into projects;
- loading it into contexts by itself (W unchanged);
- replacing plugin skills (they link to guide topics).

`HUB_TOOLS` and the plugin version change. Its spec is written in a later run.

**A criterion fixed now, G7:** the guard LG-8 in `crates/specengine-eval/tests/anonymity.rs` (`cyrillic_exemption_is_exactly_the_two_fixture_directories_and_the_catalog`) stays green with `docs/guide/**` and RM-0128's preset example practices added. Mutation: plant a Cyrillic line in a guide page, and LG-8 turns red.
