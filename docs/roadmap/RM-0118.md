# slow-requests (patch 0.46.1, operability): the daemon names its slow requests and long turns

On 2026-11-14 the owner saw the hosted hub hang for minutes, at about 14:01-14:12 UTC. The container did not restart and there was no OOM. Nothing said which request was slow: the daemon logs no requests and Traefik keeps no access log. Every CLI equivalent measured afterwards on the hub was fast: review 40-60 ms, inbox 108 ms over 154 open items, check 1.1 s, map 0.5 s.

The fix collects evidence for next time. A stderr line covers a request past a threshold, giving its route template, its wait for the project's turn and its run inside it, and whether it walked. Another line names a turn held past the threshold by anyone, the `--push` sync included, while it is still held. Traefik's access log is turned on, slow requests only, with fields from an allowlist.

Spec: `docs/features/slow-requests.md`, no ADR. It ships in the patch release 0.46.1 with the other items RM-0114 to RM-0119.

Shipped 2026-11-14 in the 0.46.1 patch: `--slow-ms`, the request and turn lines, Traefik's access log. Canon: `docs/canon/serve-slow.md`.
