# door-reset-totp (pool): `hub-admin reset` of a person with no TOTP reports a TOTP left

Found by RM-0130's review, 2026-11-20. `hub-admin reset` deletes a person's passkeys and TOTP. For a person who never registered a TOTP, the pinned door's `totp delete` exits 1, so `reset` warns `TOTP not deleted` and logs `totp-left` (`hub-accounts.md` AC19 pins that answer). The reset itself completes, so the audit line misleads but nothing is blocked.

**The developer's record** (`authelia/authelia` 4.39.28, the pinned digest, 2026-11-20): `storage user totp delete` of a login with no TOTP answers `Error: failed to delete TOTP configuration for user '<login>': no TOTP configuration for user`, exit 1.

**The fix asks for:**
- that answer recorded on the pinned image, as `hub-backups.md` HB5 recorded the storage calls, and the test double taught it;
- `reset` reading it as "nothing to delete", with no warning and no `totp-left`; any other failure keeps today's warning;
- AC19 rewritten to match.

**The owner's question** (asked 2026-11-20, open): should "no TOTP to delete" stay a warning in the act log, or read as nothing to delete?
