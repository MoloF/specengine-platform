# hub-git (Phase 7, step 10b): fetch, merge and push, never rebase, with a push status on screen

The hub, by convention the sole writer of a brief zone, works on a sparse clone of the game's own repository holding the paths its `specengine.toml` names (`spec sparse-set`). It fetches, merges and pushes, never rebases, because the queue stores `applied_commit`; a failed push shows on screen and retries. Issues `hub-push`. No `crates/*/src` runs git's `push`, `pull` or `fetch` today. This step begins at the first network verb: from `hub-confirm` (RM-0050) on, a confirm already commits in the hub's checkout, so this step has its caller, and until it ships `applied` means committed on that hub. From `apply-outputs` (RM-0072) on, that commit carries the index and a hub's `PR-` numbers have their own range, so nothing pushed here stops another person's hook or reject. The branch is the owner's decision (Q1, closed). 3-4.5 pipeline hours.

From the analysis of 2026-11-03; the spec is `docs/features/hub-git.md` (criteria P1-P23, U1):

- **The branch** (the owner's decision, 2026-11-03, closing Q1): the hub pushes to the game's main branch, the branch its checkout tracks. A merge commit appears only when the hub and a developer have diverged. A linear-history protection on that branch is lifted for the hub, which RM-0064's deploy guide states.
- **The first network verb.** An opt-in flag, `--push`, valid only with `--public-origin`; a separate sync, never inside a confirm; `GIT_NO_LAZY_FETCH=1` on every other worktree git child.
- **Merge, never rebase.** No `git pull`, rebase, force, reset, `--allow-unrelated-histories` or `-X`; a conflict aborts and leaves no `MERGE_HEAD`; the merge commit carries no trailer and the checkout's identity. Every merge commit carries the index's outputs rendered from the merged tree, so a conflict in them alone resolves; this step widens the canon's generated rule to it (RM-0072's ADR keeps "an apply's commit").
- **Sole writer** is a convention, unenforced (decided): developers' terminals may still apply in the brief zone.
- **Credentials** belong to git, configured by the deployment; no `src` names one, and a remote URL with userinfo is refused.
- **A conflict** (decided): the operator resolves it on the host's terminal while the hub keeps confirming locally and shows "N not pushed".
