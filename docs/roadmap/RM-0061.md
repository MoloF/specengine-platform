# pack (Phase 7, v5 step 11): `spec init --pack` and a non-game preset

A template pack is files outside the core (ADR-0008): `[ids]` prefixes, `[[check.rules]]`, card flows, vocabulary in the project's language over the chrome in English or Russian (owner's decision 10, amended: ADR-0072). `spec init --pack` installs one. Three game fixtures and a non-game one guard against a word leaking into the core. 3-4 pipeline hours (its analysis of 2026-11-12).

Deferred to the next release, `v4`, on 2026-11-04: the owner's instruction to do only what the hub's release to a server needs (08 s2 Phase 7, "Release scope").

Since 2026-11-08: v4 step 1a `workspaces` (RM-0081) ships the gamedev preset ahead of this step, as a fixture-tested file outside the core; `spec init --pack` and the config proposal stay here. The "English interface" of decision 10 is amended by ADR-0072 `ui-languages` (RM-0082), the chrome in English and Russian, each viewer's choice (08 s2 Phase 7, "v4 scope"); a pack's vocabulary stays project data, never a catalog key.

Since 2026-11-10: `v5` (08 s2 Phase 7, "v5 scope"). Presets are copied and extended by `spec init --pack` (Q10), with department titles from RM-0096, and a non-game preset ships beside the game one to keep the core domain-free.

Since 2026-11-12 (08 s2 Phase 7, "Owner's word, 2026-11-12"): the fifth core slice, CLI only, a pack by path. The config proposal, a writer's type change reviewed as a proposal, leaves it for RM-0110 `config-proposal`, which needs its own ADR. Its spec `docs/features/pack.md`.
