# inbox-closed-link (patch 0.46.1, a fix): a link to a decided proposal shows that proposal

The owner hit this on 2026-11-14, on the hosted hub (0.46.0, his game project). He followed a link to PR-100155, an applied question decided into DEC-100002, and the Inbox showed a different proposal. Because `GET …/inbox` lists only open and approved items, the routed ID was missing from the list. `InboxView` then selected the first open item under that URL, with only a note saying so.

The fix reads the routed proposal on its own, through `GET …/proposals/<id>`, which serves any status. It is shown read-only: what was decided, by whom, when, in which commit and into which record. Nothing is selected in its place.

Spec: `docs/features/inbox-closed-link.md`, no ADR. It ships in the patch release 0.46.1 with the other items RM-0114 to RM-0119.

Shipped 2026-11-14 in the 0.46.1 patch: `ClosedProposal`, read alone, nothing selected. Canon: `docs/canon/proposal-review.md` "Inbox".
