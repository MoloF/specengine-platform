# department-split (Phase 7, v5 step 6c): a task and a subtask per department, in one act

Re-scoped on 2026-11-11 from `journeys` (optional, a soft `after`) by the owner's vision (08 s2 Phase 7, "Owner's vision, 2026-11-11"): a writer describes the game, and it is split into subtasks per department. The spec is `docs/features/department-split.md` (draft, 2026-11-11, 17 criteria), with ADR-0078 `card-split`, which supplements ADR-0056, ADR-0074 and ADR-0076 (`docs/canon/card-split.md` "The rule"). 10-15 pipeline hours: the Rust lane 6-9, the UI lane 4-6, in parallel. Plugin 0.37.0.

- **One act**: a parent task on a document, or a stored task, and one subtask per chosen discipline, each with the parent's reviewer, placed by the new-card rule; one transaction, all or none.
- **Templates**: `[[card.split]] kind = ... disciplines = [...]` under `[card]` pre-selects disciplines and picks each subtask's targets, the nodes of its kinds, else the document; it never refuses.
- **Interfaces**: `spec card split` and its `--dry-run`, MCP `split_card` (stdio and a hub), `POST .../cards/split`, a hub's seventh plain write; one lazy dialog from the document, Flow's panel and a task.
- **The preset** gains a `sound` flow and department and commented split rows; `card-press` carries two live rows.
- **Left out**: the old item's soft `after`; the mandate is RM-0104 `task-mandate`, the next slice.
