# question-accept-note (patch 0.46.1, a fix): a question's Accept says the note is not the answer, and takes an own answer

The owner reported this on 2026-11-14 while using the hosted hub (0.46.0, project `dorm`). He wrote in Russian; paraphrased: on a question proposal, the Inbox's Accept dialog has one text field, and it is only a decision note. The dialog does not warn about that, and the text does not reach the Questions screen as an answer. So a person who typed an answer there decided the working answer, with their words as a note beside it.

His ideas were an "Own answer" in this dialog, as the Questions screen has, or a warning when the note diverges from the working answer. It was first filed to the pool. The same day he scheduled it with the other fixes ("do all the fixes and release a new version"), and the spec takes both ideas.

It is UI-only: the stage already takes `answer` (`docs/canon/decision-staging.md` "UI"). Spec: `docs/features/question-accept-note.md`, no ADR. It ships in the patch release 0.46.1 with the other items RM-0114 to RM-0119.

Shipped 2026-11-14 in the 0.46.1 patch: Own answer and the note's warning in the Inbox's Accept. Canon: `docs/canon/plain-questions.md` "UI".
