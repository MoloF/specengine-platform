# board-in-git (Phase 7, step 10c): the board's snapshot on a dedicated branch

Git is the store, a thin server the door (owner's decision 1). The server pushes a snapshot of the board to a dedicated branch, so history on the main branch stays clean; CI validates each push; the board can be rebuilt from git, losing only the last minutes. Issues `board-snapshot`, which amends ADR-0003: `docs/canon/architecture.md#storage` and `docs/canon/queue-export.md` keep the queue's dump out of git today. 2-4 pipeline hours.

Deferred to the next release, `v4`, on 2026-11-04: the owner's instruction to do only what the hub's release to a server needs (08 s2 Phase 7, "Release scope").

Moved to the pool on 2026-11-10 with v4's unstarted tail (08 s2 Phase 7, "v5 scope").
