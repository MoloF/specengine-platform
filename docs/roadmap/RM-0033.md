# lock-diff: what changed since the lock, beside a drifted binding

For each drifted binding whose row has a `spec.lock` entry, this shows the node's text at the entry's `commit` and the bound code at its `file_blob`, each against the working tree, as git's hunks. The owner then sees what moved before deciding. Sources: 05 s5.3, 06 s4, and `docs/canon/spec-lock.md` "Entry". It was moved out of RM-0011 on 2026-10-21 (Q-A).

ADR-0053 (accepted 2026-10-21 under the owner's pre-approval, review open) adds to ADR-0046: hunks inside a read, git's `diff --no-index` the one exception to the reads' git list (`docs/canon/architecture-code.md` "Sync in reads"; the rules: `docs/canon/spec-lock-diff.md`). Q-E to Q-I were decided as the breakdown recommends. Done: both slices shipped, in this order:
1. `lock-diff`: `spec lock diff REF [--json]`, the daemon's `lock-diff?ref=`, five key sets and the UI's types and client call (`docs/features/lock-diff.md`), shipped 2026-10-21;
2. `lock-diff-ui` (the breakdown's slice 5, the last): the "Changes since the lock" disclosure in the node's Bindings tab, read on first expanding, never when the tab opens; under each kept row its sides as `DiffView`s, hunks as sent, and its commands; UI only (`docs/features/lock-diff-ui.md`, `docs/canon/lock-diff-panel.md`), shipped 2026-10-21.
