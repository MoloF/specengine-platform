# Proposal review: inbox, review document, preview

What the owner and agents read of the queue: `spec inbox`, `spec review PR`, and the review document, the JSON of `propose`, `review`, `approve`, `reject` (MCP `get_proposal`, the daemon's and the UI's `Proposal`). Flags, outputs of the other commands, exits: `proposal-queue.md` "Commands"; `--brief`, the intake keys: `agent-intake-documents.md` "Review document". Review writes in no worktree. Code: CLI `inbox.rs`, `review.rs`, `proposals.rs` (the document); MCP `mirror.rs` (its schema).

## Inbox

`spec inbox [--all]` -> the current repository's `open` and `approved` (`--all`: every state) by ID number, `<id> | <kind> | <status> | <target_id> | <branch> | <created_at> | <rationale's first line>` (over 80 characters: 79 + `…`; an intake's `<severity>: <gist, else summary>`, a drift item's summary alone); text state `open (staged)` for a staged one (`decision-staging.md`). JSON `{proposals: [{id, kind, status, target_id, target_ids, branch, created_at, rationale, severity, summary, gist, record_id, staged_at}], notes}` (13 keys; `gist` a question's: `plain-questions.md` "Documents"), `target_ids` every target (an update: `[target_id]`). Notes (`note:`, JSON `notes`), exit 0: ``<n> proposal(s) of another repository of the project `<slug>` not listed: `spec inbox` lists the current repository's``; ``<n> proposal(s) of a repository that no longer exists not listed: <IDs>; `spec reject <ID> --reason …` takes …`` (10 IDs, then ` … and <k> more`); a corrupt row: ``proposal PR-0003: the stored `<column>` cannot be read: <why>; not listed``. Known limit: `inbox --all`'s gone note lists gone applied and rejected IDs too.

**Read row by row** (RM-0134, store `each_readable`): the store steps the statement and hands each row to the caller as it decodes, keeping none; the visitor never calls the queue, whose read transaction is open. `list_readable` collects it for the other callers; `list` (tests only) still reads every row. A filter naming states is applied in SQL, and a row whose state is NULL or none of the four always comes, noted as unreadable; every column is selected, so a corrupt row is named by the first column that fails. The inbox keeps a current-repository row as its entry (`approve --open`: the `Proposal`), and another repository's as two counts and at most 10 gone IDs. One read peaks about 1.6 KB per pending item against a 304 B answer each (6.6 KB before).

**The Inbox screen** (`src/inbox/`). The selected proposal (`ProposalCard.tsx`) is an `IssueView` pane (`ui-design.md` "The work item"): Breadcrumbs Project, Inbox, its ID current; the title `h2`; its status a `Lozenge` from `labels.ts` `statusLozenge(value, t)`, the one proposal-status table (the Board's `itemStatusLook` delegates), an unknown value neutral, raw, `lang="en"`; the decision bar as `Button`s, Accept primary, Reject danger, the rest default, each keeping its key; a drift item's terminal commands, no primary; a staged choice's Confirm takes the primary on a hub (`hub-confirm.md` "Screen"). Side: Details, a `PropertyList` (kind raw, gap type, severity, agent task, the Board's task). A served `pair` lays the evidence out by side (`agent-intake-documents.md` "Pair"). Its main ends with References, then Comments, under its ID (`work-references-surfaces.md`, `comments-surfaces.md` "Screen"), the closed view's too. **A routed proposal the inbox does not list** (`#/<p>/inbox/<PR>`: decided, or unknown) is read alone by `useProposal` (`GET …/proposals/<id>`, any status) and shown read-only, `ClosedProposal.tsx` (lazy), an `IssueView`: the trail; the gist, else the summary, `target_id`, the kind; its status `Lozenge`; the line "This proposal is no longer in the inbox. It is shown to read; nothing here decides it."; Details Kind, Decided by, Decided at, Commit (the full SHA as text), Record (a `DocLink` by `record_title`, else `record_id`, else `record_path`), Targets, a null row left out; the decision note as text. No decision bar. No list item is selected, the route stays, `j`, `k`, the arrows, Home and End select from none, and a decision letter announces "`<PR>` is not in the inbox: nothing to decide here." The exit-1 document says "`<PR>`: no proposal has this ID in this project.", no pane; a failed read its message, Retry. A just-raised open item shows there until the inbox lists it; one decided elsewhere while routed turns into its closed view; this view's own Confirm replaces the route with `#/<p>/inbox`. A clear queue shows the pane beside its empty state. The empty queue and a filter with no match are `EmptyState`s, level 2, Clear filter the latter's primary. A trail's Project is `api/queries.ts` `useProjectName(p)`: the Shell's projects read, passive (`enabled: false`, so a trail adds no read), the slug until it answers; the Spec tree's node uses it too.

## Review text

`spec review PR` -> every document key as `key: value`, absent `-`; `base_text`, `new_text`, `rationale`, `diff`, `conflict`, `decision_note` as blocks indented two spaces; `diagnostics`, `notes` as `key: <n>` and an indented line each; `staged:` compact JSON, `staged_at:`; `drift: <n> row(s)` (stored plus `more`), each stored row indented two spaces in `spec verify`'s row form (`spec-verify-output.md` "Text"; a keyless binding `-`), then `  … and <k> more`; `drift: -` on other kinds.

## Review document

Every key, absent = `null`, none starting `block`; 56, in this order:

`{id, project, kind, status, target_id, target_path, worktree, branch, base_commit, base_hash, base_text, new_text, patch_hash, rationale, author, diagnostics, diff, preview, conflict, revisions, drift, decided_by, decided_at, decision_note, applied_commit, created_at, updated_at, <fourteen intake keys>, <a record's five>, task_id, staged, staged_at, interpretation, card_id, why, comment_id, similar, notes, cited}`

Keys defined elsewhere: `cited`, the last key of every proposal document, filled by `review --json`, `get_proposal`, `review_proposal` and `proposals/:id`, else `null`, no text line: `card-practices.md`; `revisions` `proposal-revisions.md` "Review"; `drift` `{hash, rows, more}` (`null` on other kinds; rows as stored, later keys kept: `--json` and the daemon keep each row's key order, MCP sorts keys, parsing into `serde_json::Value`) `proposal-drift.md` "Review, stage, round"; the fourteen, `target_ids` to `linked` (`pair`: "Pair" there), `agent-intake-documents.md` "Review document"; `record_id` to `choice` `decision-record.md` "Queue and documents"; `task_id` `tasks.md` "Task-bound proposals"; `staged` (the stage object or `null`), `staged_at` `decision-staging.md` "The stage"; `interpretation` `proposal-interpretation.md` "Row and review"; `card_id`, `why` `card-questions.md` "Store"; `comment_id` `comments.md` "Turning into an item"; `similar` `proposal-similar.md`. `diff`: base -> new hunks of the store's `diff_hunks` under `--- base <path>`, `+++ proposed <path>` (from the worktree top).

**`diff_hunks`** (review's `diff`, the package's `snapshot_diff`, `spec lock diff`; store `WorktreeGit`, its git rules `proposal-queue.md` "Terminal and git safety"): `git -C <data dir> -c core.attributesFile=/dev/null diff --no-index --no-color --no-ext-diff --no-textconv --diff-algorithm=myers -U3` with `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_ATTR_NOSYSTEM=1`, `GIT_CEILING_DIRECTORIES` the data directory's parent, no `GIT_DIFF_OPTS`: no repository's config or attributes, git's defaults alone; a pair git deems binary (a NUL byte) has no hunk, so review and the package read it as equal (`spec lock diff`: `null`).

**Pinned**: `fixtures/daemon-keys.json` holds the UI's key sets (187), among them `Proposal`, `InboxEntry`, `Pair`, `PairSide`, the stage's two shapes (`StagedApprove` 7 keys, `StagedReject` 2) and `DriftEvidence` (`hash`, `rows`, `more`; rows `StoredDriftRow` in the UI, unpinned). MCP `get_proposal` = `review --brief --json`, its output schema's `staged` two closed objects, `drift` `DriftShape`. UI `daemonKeys.test.ts` compares the provisional types with the file, set by set in the slices' order; its `AHEAD_OF_FIXTURE` (keys served before the file has them) is empty, and a listed key the file names fails. Backups keep stages (`queue-backup.md` "Format").

## Preview

`preview` (open, approved; a drift item's `null`, no walk, note ``spec approve PR shows the rows before asking``): apply steps 2-6 (`proposal-apply.md` "Apply steps") read-only -> `applies`, `rebases`, `conflicts` (+ `conflict`, the merge's text) or `unavailable` (note `not applicable now (step <n>): <reason>`; a raise refused: `proposal-revisions.md` "Review"); its own commit on the branch -> `unavailable`, steps not run, note ``its commit <sha> is on `<branch>`: `spec approve PR` completes it; no new apply is needed``; a lookup git cannot make -> note ``cannot tell whether its commit is on `<branch>`: <why>``.
