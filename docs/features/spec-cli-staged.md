# The spec CLI, pass 2a.2: check --staged

## Why

2b's pre-commit hook (Q6) must vouch for the tree the commit records (`GIT_INDEX_FILE`'s index, `commit -a`/`-o`'s included), not 2a.1's working tree; `check_source` stays. No new ADR: read-only git truth, worktrees, no daemon (ADR-0001, ADR-0003, ADR-0004, ADR-0006). What shipped is canon in `docs/canon/spec-check-cli.md` ("The staged check": git use, environment, guard, causes, divergences; "Open") and the store and CLI READMEs.

## Implementation

Four iterations (the fourth an owner-approved extra); review accepted the fourth, nothing blocking. Full run 862 passed, 15 skipped. (1) All of it: git plumbing, `GitIndex`, `check_staged`, `--staged`; the detector is `diff-files -z --name-only --no-renames --ignore-submodules=all --diff-filter=A --ita-invisible-in-index --relative`, not `status` (which paired an ita file with a deleted empty one as a rename and reads `HEAD`). (2) Relative `GIT_INDEX_FILE` (a plain commit's hook exports `.git/index`, top-relative), `GIT_OBJECT_DIRECTORY`, `GIT_COMMON_DIR` resolved by `rev-parse`; the detector narrowed to empty `.md`, config, baseline blobs; AC-13's `--filters` mutation given `<oid> <path>` requests to bite. (3) The guard: a linked worktree's `cd proj` hook had passed the top project (a false `clean`). (4) The guard's discovery without `GIT_CEILING_DIRECTORIES`, with `GIT_DISCOVERY_ACROSS_FILESYSTEM=1`, plus `--absolute-git-dir` against `GIT_DIR` (a submodule, a ceiling at the linked top had passed); two calls, as a path may hold LF; same directory: canonical paths or (dev, ino), as given when canonicalising fails.

| Module | What it does |
|---|---|
| store `git.rs` | `GitEnv`; children's environment (resolution, guard `is_not_top_of`, `same_dir`); `ls-files -s -z` parsing; lockstep `cat-file --batch`; the detector; `Staged` |
| store `source.rs` | `GitIndex: Source`; `related_to_a_root`, shared with `WorkingTree::is_dir` |

Tests: cli `staged.rs`, `staged_git.rs`, `staged_hook.rs`, `staged_load.rs`, `staged_helper.rs`, `common/{git,staged}.rs`; store `staged_walk.rs`, `genre.rs`; eval `build_graph.rs`.

Accepted deviations: `rev-parse --is-inside-work-tree` first, for a precise "no repository"; every unmerged path under the root a cause, not only documents; `cat-file`'s stderr discarded; empty `GIT_INDEX_FILE` = names no file; the guard also goes on for `GIT_DIR` = the top's own `.git` gitfile, on empty output or a vanished cwd; its message also covers a top whose `GIT_DIR` names another repository or none; `core.worktree` set aside under `GIT_DIR` alone; a `GIT_DIR`-only tree without `.git` in a ceiling-hidden repository is refused. The guard is complete only for layouts git creates; R11 (`--root` from the top) is the mitigation. A walked-empty ita `.md` could hide a broken link to it (rare).

Review's fixes for the canon's guard residues: (a) one `rev-parse --show-toplevel` honouring `GIT_DIR`, refused unless the cwd; (b) `-c safe.directory=*` on the guard's calls, refuse when the first fails beside a `.git` entry; gitfile nit: also `same_dir(git_dir.parent(), cwd)`; message nit: go on when `GIT_DIR` does not exist, or widen it.
